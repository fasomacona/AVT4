¿Qué es ETL?

Extract – Transform – Load: extraer datos de orígenes, transformarlos (limpiar, tipificar, combinar) y cargarlos al modelo analítico. En Power BI, la herramienta central es Power Query (editor de consultas).

4.2.1 Fuentes de datos

TipoEjemplosNotas
ArchivosExcel, CSV, JSON, XML, carpetaIdeal para prácticas y prototipos
Bases de datosSQL Server, PostgreSQL, MySQL, OracleImport o DirectQuery
Servicios en la nubeSharePoint, Dataverse, Azure, Google AnalyticsRequieren credenciales
Web / APIPáginas HTML, RESTÚtil para datos públicos
Import vs DirectQuery: Import copia datos al modelo (más rápido al interactuar); DirectQuery consulta la fuente en vivo (datos frescos, más restricciones de rendimiento).

4.2.2 Transformación de datos

Operaciones frecuentes en Power Query:

  • Promover encabezados, cambiar tipos de datos.
  • Filtrar filas, quitar/renombrar columnas.
  • Reemplazar valores, dividir columnas, rellenar.
  • Despivotar (unpivot) para normalizar tablas “anchas”.
  • Combinar consultas: append (apilar) y merge (join).
  • Agrupar y agregar.

Cada paso se registra en el panel de Pasos aplicados (reproducible y auditable). El lenguaje subyacente es M.

4.2.3 ETL avanzado

  • Parámetros: rutas de archivo, fechas de corte, entornos (dev/prod).
  • Funciones personalizadas: reutilizar la misma lógica en varias consultas.
  • Carpeta de archivos: combinar muchos CSV/Excel con el mismo esquema.
  • Consultas de referencia vs duplicadas: una base limpia y varias derivadas.
  • Manejo de errores: tipos incorrectos, filas problemáticas, valores nulos.
  • Actualización incremental (en el servicio Power BI, escenarios grandes).

Buenas prácticas de Power Query

  1. Nombrar consultas y pasos con sentido de negocio.
  2. Tipos de datos correctos antes de modelar.
  3. Eliminar columnas innecesarias (menos memoria).
  4. Evitar lógica de negocio compleja en M cuando pertenece a DAX o a la fuente.
  5. Documentar orígenes y reglas de limpieza en el README del proyecto.
