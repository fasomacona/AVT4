4.3.1 Conceptos del modelo tabular

Power BI usa un modelo en estrella (star schema) idealmente:

  • Tablas de hechos: eventos medibles (ventas, tickets, movimientos) con claves y métricas.
  • Tablas de dimensión: contexto (producto, cliente, fecha, región, empleado).
  • Relaciones: normalmente 1:* desde dimensión hacia hecho; dirección de filtro controlada.
Tabla de fechas (Date/Calendar): imprescindible para inteligencia de tiempo (YTD, mismo periodo del año anterior, etc.). Debe ser continua y marcada como tabla de fechas.

4.3.2 Expresiones de análisis de datos (DAX)

DAX (Data Analysis Expressions) calcula columnas, medidas y tablas. La diferencia clave:

ObjetoCuándo se calculaUso típico
Columna calculadaAl procesar el modelo (fila a fila)Clasificaciones, claves auxiliares
MedidaAl interactuar con el informe (contexto de filtro)KPIs: suma, promedio, % , YTD

Medidas básicas (ejemplos)

Ventas = SUM( Hechos[Importe] )

Ventas LY = CALCULATE( [Ventas], SAMEPERIODLASTYEAR( 'Fecha'[Fecha] ) )

% Var = DIVIDE( [Ventas] - [Ventas LY], [Ventas LY] )

Contexto de filtro

Las medidas responden al contexto de los visuales (segmentadores, filas de una matriz, etc.). Funciones como CALCULATE, FILTER, ALL, REMOVEFILTERS modifican ese contexto.

4.3.3 Optimización del rendimiento

  • Preferir medidas frente a columnas calculadas pesadas.
  • Reducir cardinalidad (menos valores únicos innecesarios).
  • Evitar relaciones bidireccionales salvo necesidad justificada.
  • Tipos de datos compactos; quitar columnas no usadas.
  • Variables (VAR) en DAX para legibilidad y a veces rendimiento.
  • Analizar con Performance Analyzer en Power BI Desktop.
Error frecuente: poner todas las tablas “sueltas” sin relaciones, o crear una sola tabla plana enorme. El modelo en estrella simplifica DAX y mejora el rendimiento.
